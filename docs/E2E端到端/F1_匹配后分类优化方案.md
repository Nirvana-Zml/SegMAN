## 1. 问题定义

### 1.1 指标含义

| 指标 | 定义 | 当前 M2F | B1 语义 | 闸门 |
| --- | --- | --- | --- | --- |
| **cls_on_matched** | GT 实例与 pred 实例 mask IoU≥0.25 匹配成功后，OpenCLIP **分类 Top-1 = GT 类** 的比例 | **81.78%** | **84.59%** | **≥ 83%** |
| match_rate | 同上匹配流程中，GT 被任意 pred 匹配的比例 | 75.46% | 59.16% | ≥ 65% ✅ |
| seg_class_acc_on_matched | 匹配对上后，**分割语义类** 与 GT 一致比例 | 89.29% | 93.20% | 参考 |

**需补齐正确数（粗算）：**

```text
num_matched = 2343
目标正确数 ≥ 0.83 × 2343 ≈ 1945
当前正确数 ≈ 0.8178 × 2343 ≈ 1916
约需多对 29～30 个实例（+1.22pp）
```

### 1.2 为何 M2F 实例更好、分类反而略降？

| 现象 | 解释 |
| --- | --- |
| match **+16pp**，cls **−2.8pp** | 分类器在 **B1 语义连通域 ROI** 上训练；M2F mask/bbox **分布漂移** |
| wall 匹配 **618→884**（+266） | 以前「只对上」的 wall 偏简单；M2F 召回更多 **难例 wall**，拉低 wall 上 cls |
| door 匹配 **301→460** | 同类：难例进入「匹配后」集合 |
| seg 89.29% vs cls 81.78% | 约 **8pp** 差距来自 **ROI 分类头**，不是分割贴错类为主 |

**结论：** 主攻 **「M2F ROI → 分类器」适配**，而非继续训 M2F 分割。

## 4. P0：Mask2Former 推理阈值与实例过滤（无训练）

### 4.1 原理

`Mask2FormerInstancePredictor` 默认 `score_thresh=0.3`（`--m2f-score-thresh`）。  
提高阈值 → 去掉低置信实例 → 常 **减少难例 ROI**，**cls_on_matched 上升**；match_rate 可能略降。

### 4.2 实验矩阵

| 实验 ID | m2f_score_thresh | min_area | nms_iou | 预期 |
| --- | --- | --- | --- | --- |
| P0-a | 0.30 | 128 | 0.5 | 复现基线 81.78% |
| P0-b | 0.35 | 128 | 0.5 | cls↑ match 略降 |
| P0-c | 0.40 | 128 | 0.5 | cls↑ match 略降 |
| P0-d | 0.45 | 128 | 0.5 | cls↑ match 可能 &lt;65% 需验证 |
| P0-e | 0.40 | 160 | 0.5 | 进一步压碎片 |
| P0-f | 0.35 | 128 | 0.6 | 更强同类 NMS |

## 5. P1：基于 M2F ROI 的分类器适配训练

### 5.1 原理

当前交付分类器：`outputs/openclip_classifier/deliver_classifier_best.pth`  
训练数据多为 **GT 或 SegMAN 语义 CC ROI**（`data/trans10k_roi_gt` 等），与 **M2F 预测 mask 裁切** 在边界、背景混入、宽高比上不一致。

**目标：** 构造 `m2f_roi_train/val`，在冻结或部分解冻 OpenCLIP 上 **短训 10～20 epoch**。

### 5.2 数据构建（建议流程）

```text
1. infer_m2f_export_coco（train split）或逐图 predict_instances
2. 对每个 pred 实例：按 mask 裁 ROI，标签 = pred 对应类（弱监督）
   更佳：与 GT 匹配上的实例用 GT 类，未匹配丢弃或作 hard negative
3. 目录结构对齐 ROIDataset：
   data/trans10k_roi_m2f/{train,val}/{class_name}/*.jpg
```

**推荐：** 至少包含 **匹配 GT 的 M2F ROI**（与 E2E 评测分布一致），必要时加入 **高 IoU 匹配** 的 `(image, gt_class, m2f_crop)` 对。

可选脚本扩展点：

- 新建 `transgrasp/pipelines/build_m2f_roi_dataset.py`（从 `pred_instances.json` + GT COCO 生成）
- 或复用 `segmentation/tools/infer_m2f_export_coco.py` + 现有 `build_roi_dataset` 逻辑

### 5.3 训练配置建议

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 初始化 | `deliver_classifier_best.pth` | 热启动 |
| clip | ViT-B-16 / laion2b | 与现网一致 |
| freeze-clip | 先 **冻结**，只训 head | 快速验证 |
| epochs | 15～25 | val 早停 patience=5 |
| aug | `p3` | 与 P3 一致 |
| class-weights | 提高 window/jar_kettle/shelf | 对齐 P0 难类 |
| 验收 | **M2F E2E cls_on_matched** | 不以离线 ROI acc  alone 为准 |

```bash
conda activate segman
cd /workspace/segman
python transgrasp/classification/train_openclip_classifier.py \
  --roi-root data/trans10k_roi_m2f \
  --work-dir outputs/openclip_classifier/m2f_roi_adapt_v1 \
  --resume outputs/openclip_classifier/deliver_classifier_best.pth \
  --freeze-clip \
  --aug p3 \
  --epochs 20 \
  --patience 5
```

## 6. P2：轻量策略（不重训分割）

### 6.1 分割类 + 分类融合（推荐试）

对 **匹配成功** 的实例：若 `seg_class == gt_class` 且 `clip_confidence < τ`，可用 **分割类** 作为预测（或 logits 加权）。

- 现状：seg_class_acc_on_matched **89.29%** &gt; cls **81.78%**
- 实现：在 `classify_instances.py` 或后处理增加 `--fuse-seg-on-low-conf 0.55`
- 风险：闸门若严格定义为「纯 OpenCLIP Top-1」，需与 `run_f1_gate_check` 口径对齐

### 6.2 难类专项

| 类 | 动作 |
| --- | --- |
| window | 略降 `m2f_score_thresh` 仅 window（需 per-class 检测分支）；或 P1 加权 2× |
| jar_kettle | 检查与 bottle/cup 混淆；reject_thresholds 单独扫 |
| door / wall | 维持 match 收益，P1 增加 door/wall ROI 增广 |

### 6.3 reject 阈值说明

`reject_thresholds_p3.json` 影响 **grasp/reject**，**不改变** `cls_on_matched`（该指标在拒识前已算 Top-1）。  
若业务看 **grasp only Acc**，可另扫；**本方案不依赖 reject 扫参过 F1-PASS-4**。

## 7. P3：流程与闸门（兜底）

若 P0+P1 后 `cls_on_matched` 稳定在 **82.0%～82.8%**：

| 选项 | 说明 |
| --- | --- |
| A. 微调 F1-PASS-4 | 83% → **82%**，需团队书面确认 |
| B. 拆分闸门 | **F1-INST-PASS**（match≥65%）+ **F1-CLS-PASS**（cls≥83%），部署可先上实例 |
| C. 维持 B1 部署 | 仅当业务强制全闸门且 cls 无法提升 |

**不建议：** 为 1.2pp 再训一轮 M2F 40k 或专攻 COCO small AP。

## 10. 风险与禁忌

| 禁忌 | 原因 |
| --- | --- |
| 再训 M2F 专攻 small AP | 对 cls_on_matched 边际收益极小，工期 1～2 周 |

| 为提 cls 大幅提高 thresh 导致 match&lt;65% | 触发 F1-FAIL / 实例闸门失败 |
| 用 B1 语义实例混评 M2F 分类 | 指标口径混乱 |

| 风险 | 缓解 |
| --- | --- |
| P0 使 match 跌破 65% | thresh 上限建议 ≤0.42，逐步扫 |
| P1 过拟合 / 遗忘 deliver | **实测**：离线 val↑、E2E cls↓；需混合 GT ROI + 低 lr + E2E 早停 |
| 融合分割类与闸门定义冲突 | 事先改 `summarize_e2e_eval` 标注口径 |

## 12. 执行摘要
